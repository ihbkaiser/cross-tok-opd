# MP-OPD A/B/C: experiment contracts and real-data diagnostic

Status: implemented; CPU tests and mocked transport integration only. No new
GPU run, model download, benchmark result, or efficacy claim. Posterior-aware
work and full online semi-Markov meta-training (D) are outside this milestone.
The current source is the portable KDFlow branch; never update a checkout used
by an active training process. Use a separate clean checkout for these tools.

## A: matched training launcher

`experiments/runai/run_single_gpu.sh GPU MODE LIMIT` keeps MB4, effective batch
64, two epochs and a 312-update scheduler horizon. LIMIT accepts 5 (canary), 50
(pilot with the same horizon), and 0 (312 updates). It does not authorize GPU
execution. MODE accepts atomic, fixed, random. Random is the existing uniform
next-length rule, NOT the histogram-matched diagnostic control below.

Environment configuration:

| Variable | Default / contract |
|---|---|
| MP_ALGORITHM | mp_opd; also span_ctkd or xtoken |
| MP_SEED | 42, training/rollout seed |
| MP_PARTITION_SEED | 43, random partition seed |
| MP_MAX_SPAN_LENGTH | 2 (atomic forces 1) |
| MP_FIXED_SPAN_LENGTH | 2, positive and no greater than max span for fixed |
| MP_PREFLIGHT_ONLY | 1 writes contract and exits before importing Ray |
| MP_XTOKEN_PROJECTION_PATH / MP_XTOKEN_PROJECTION_SHA256 | required for xtoken; checksum verified |

Use mode `atomic` as the neutral slot when MP_ALGORITHM is span_ctkd/xtoken;
this does not convert their losses into MP-OPD. X-Token still needs its audited
model-pair-specific projection and a separate GPU canary. No DPCA port added.

Manifest records effective options, input-file SHA256, model weight/config/
tokenizer-file hashes, source commit/tracked dirty status, and installed runtime
versions. Hashing large checkpoint files takes time and is announced in logs.
It separately records sampling temperature, raw path-credit temperature (1),
and MP parity mean/p99 thresholds. Non-MP algorithms do NOT inherit MP parity.
Evaluation remains linked by an external pinned eval manifest; launcher does
not run evaluation or silently choose an eval protocol.

Examples (only run training after choosing a free GPU):

```bash
# CPU preflight, hashes files but never initializes models/Ray:
MP_PREFLIGHT_ONLY=1 MP_SEED=43 MP_MAX_SPAN_LENGTH=4 MP_FIXED_SPAN_LENGTH=4 \
  bash experiments/runai/run_single_gpu.sh 1 fixed 5
# New, separate run after reviewing preflight:
MP_SEED=43 MP_MAX_SPAN_LENGTH=4 MP_FIXED_SPAN_LENGTH=4 \
  bash experiments/runai/run_single_gpu.sh 1 fixed 5
# Set LIMIT=50 for pilot or LIMIT=0 for full only after a successful canary.
```

## B: independent-data oracle

`experiments/mp_opd/real_oracle.py` has separate prepare/run subcommands.
Preparation reads JSONL or Parquet with chat messages and an EXPLICIT string
reference column. For SFT chat records whose final message is the teacher answer,
explicitly use `--reference-key @last-assistant`: the final assistant message
becomes the reference and is removed from the prompt. Exclusion files likewise
strip their final assistant target before hashing. It never guesses that a numeric label is a reference answer.
Use train/dev references, not benchmark test answers. Data quality and exclusion
from external benchmark sets remain a caller obligation. No existing company
dataset is modified.

`--exclude-prompts PATH` may be repeated for SFT/train/test prompt files or a
previous prepared oracle JSON. It excludes exact prompt-content hashes across
ALL three roles and records source hashes. This is conservative; if only an old
SFT pool exists it can be used for mechanics, but cannot establish unseen-prompt
generalization. Splitting a previously trained-on corpus does not undo exposure.
Near-duplicate/semantic overlap still needs a separate dataset audit.
`--reference-provenance` records the teacher/generation artifact identifier.
Reusing held-out SFT teacher responses is valid; a different teacher is not
required. Generate new responses only for new prompts without retained labels.

Preparation shuffles sorted content IDs reproducibly, deduplicates prompts,
rejects conflicting references, and builds three disjoint rows per group:
rollout B, M_select, M_eval. Prompt hashes enforce separation even when external
IDs differ. Default 32 groups needs 96 distinct reference-bearing prompts.
Reference text is removed from the rollout record. Output uses exclusive create.

```bash
/usr/bin/python3.12 experiments/mp_opd/real_oracle.py prepare \
  --input /absolute/path/to/nonbenchmark-references.jsonl \
  --reference-key reference --groups 32 --seed 42 \
  --output /workspace/storage-shared/nlp/tungks/mp-oracle-groups.json
```

First use `--groups 2` for a separate diagnostic canary file. Do not reuse the
canary eval examples to tune the full diagnostic; prepare the full file from a
disjoint source or explicitly exclude those IDs. A run does not choose the
reference source automatically. JSONL preparation is stdlib-only; Parquet uses
the existing datasets package without installing it.

The run backend loads local HF student/teacher models with eager attention,
freezes their parameters and attaches one zero-output rank-r probe to an explicit
Linear module. Only its FP32 B matrix participates in virtual SGD. This is NOT
full-parameter Adam, an existing trained LoRA, a KDFlow training continuation,
or an SGLang backend parity test. Both models are on the one selected device.
No model is saved/modified; generation and scoring execute no generated code.

Example for Gemma2-2B (verify module name/model architecture before use):

```bash
CUDA_VISIBLE_DEVICES=1 HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
  bash experiments/runai/python-b200-host.sh experiments/mp_opd/real_oracle.py run \
  --student /absolute/path/to/chosen/student-checkpoint \
  --teacher /workspace/storage-shared/models/Qwen2.5-7B-Instruct \
  --data /workspace/storage-shared/nlp/tungks/mp-oracle-groups.json \
  --output /workspace/storage-shared/nlp/tungks/mp-oracle-UNIQUE-RUN \
  --adapter-module model.layers.25.self_attn.q_proj \
  --device cuda:0 --rank 4 --virtual-lr 0.01 --max-span 4
```

0.01 is an explicit diagnostic probe step size, NOT a recommended training LR.
Calibrate a small step on separate development groups and compare predicted vs
actual select loss before interpreting held-out gains. The adapter scale makes
the training LR 1e-6 inapplicable without calibration. The 5h30 full-run estimate
does not apply to this diagnostic; time two groups before choosing a budget.

Student sampled IDs are retained before terminal stripping; content IDs are
used for teacher retokenization and exact byte atomization. Gemma end-of-turn
and EOS controls follow the existing atomizer policy. Credit uses raw model
logprobs, normalized by valid student token count. Outer objective is supplied
reference-token mean NLL including tokenizer EOS; it is a specified diagnostic
objective, not the paper benchmark grader. Prompt/reference caps reject excess
length instead of truncating silently. Responses capped by generation are
recorded with sampled_eos=false. No interpretation as exact text-KL is made.

Per group, directional scores use M_select only; hard DP chooses the maximum
first-order utility partition. Each candidate receives an actual functional
virtual update and is evaluated on M_select and independent M_eval. We verify
that real probe parameters stay unchanged and never create a real student
optimizer. Invalid atomizations are logged/excluded, and zero valid groups fail.
Model and data hashes, seed, subspace, settings, trajectories and base credits
are saved. Traces may contain company data: keep them on company storage; do
not include them in source bundles or automatically upload them to W&B.

## C: controls and learned weighting

Every valid group reports atomic, fixed2, fixed4, oracle, skip, half/quarter LR
atomic, atomic scaled to oracle gradient norm, meta-reference SFT update, learned
atom weighting and random partitions matching the oracle length histogram.
Fixed2/fixed4 are explicit controls even when the oracle max-span cap is smaller.
A zero atomic gradient is flagged; its direction cannot be normalized to a
nonzero oracle gradient. The norm control then stays zero, not a matched norm.

Random permutes the oracle span lengths, preserving full coverage and count.
It shares the select-derived length histogram but not the boundary locations.
If lengths are identical (or a shuffle returns the same order), the report flags
`random_degenerate`; do not count it as an independent informative comparison.

Learned weighting is a 3-feature (rate, credit, log student length) MLP. It starts
at identity, preserves credit signs and token-weighted mean multiplier one.
It does NOT conserve signed total credit. Meta gradients differentiate the
virtual step exactly; only its optimizer is stepped. Evaluation is prequential:
current group is reported BEFORE learning from its M_select. Thus the first
learned result is identity, and later groups have progressively more training.
No M_eval is used for fitting. A checkpoint includes optimizer and data identity;
this milestone does not add a resumable full-training weighting mode.

A full MP-soft comparison must later match meta-data exposure, feature access,
network capacity/tuning and compute, and train weighting on fixed meta-train
splits before final held-out evaluation. Prequential diagnostics alone cannot
establish superiority of structured partitioning over fully trained weighting.

## Evidence and decision gate

`results.jsonl` reports select/eval loss, actual eval improvement, gradient norm,
predicted select improvement and partitions. `summary.json` gives paired oracle
comparisons to ALL controls, positive fractions and exploratory bootstrap
intervals. Groups are small and the weighting control learns sequentially;
bootstrap intervals are descriptive, not a formal independence guarantee.

Do not infer pass from mean gain alone. Require stable actual eval gains over
skip, LR/norm controls and weighting; inspect invalid rate, sampled termination,
variance, step-size sensitivity and real memory/time. An adapter-only result
requires a separate transfer check before justifying full-parameter MP-soft.
No automatic scheduling, GPU allocation, W&B upload, or generated-code grader
is included. Full semi-Markov energy training remains milestone D.

Conflict handling: preparation remains strict by default. Explicit
`--conflicting-references exclude` excludes the ENTIRE exact-prompt group when
multiple distinct references occur, independent of row order; it never selects
a shortest/first answer as truth. The mechanics script opts into this policy.

population and does not solve prior SFT exposure or semantic near-duplicates.
