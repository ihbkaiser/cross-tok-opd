# SimCT B200 portability profile

For a from-scratch company-server setup—including restricted outbound network,
internal package pools, internal model paths, TLS/auth handling, and SFT/SimCT
qualification—follow the [detailed B200 installation runbook](B200_INSTALL.md).

The B200 profile is intentionally split into two locked Python environments:

- `simct-b200-sft`: LlamaFactory warm-start/SFT work.
- `simct-b200`: KDFlow, SGLang, and SimCT on-policy distillation.

Both use Python 3.12, CUDA 13.0 user-space packages, Torch 2.11, and target
Blackwell compute capability `sm_100`. Keeping the environments separate avoids
coupling LlamaFactory's Transformers release to the SGLang/KDFlow runtime.

## Company-machine prerequisites

- Linux x86_64 with one or more NVIDIA B200 GPUs.
- NVIDIA driver exposing a CUDA 13.0-compatible Driver API.
- CUDA 13.0 development toolkit (`nvcc` is required by the gate).
- `uv==0.12.7`.

Install without changing either lock:

```bash
UV_PROJECT_ENVIRONMENT=.venv-sft uv sync \
  --project experiments/environments/simct-b200-sft --locked
UV_PROJECT_ENVIRONMENT=.venv-simct uv sync \
  --project experiments/environments/simct-b200 --locked
.venv-sft/bin/python experiments/environments/patch_llamafactory_json_path.py
```

The pinned LlamaFactory 0.9.5 wheel has a Python 3.12 parser bug that passes a
`Path` directly to `json.load`. The Modal image applies the narrow,
fail-closed compatibility patch in `patch_llamafactory_json_path.py`; the
image build stops if the exact upstream source pattern is not present once.

Run the hardware gate in each environment:

```bash
TORCH_CUDA_ARCH_LIST=10.0 CUDAARCHS=100 CMAKE_CUDA_ARCHITECTURES=100 \
  .venv-sft/bin/python experiments/environments/b200_gate.py
TORCH_CUDA_ARCH_LIST=10.0 CUDAARCHS=100 CMAKE_CUDA_ARCHITECTURES=100 \
  .venv-simct/bin/python experiments/environments/b200_gate.py
```

## Qualification tiers

1. Environment gate: imports, driver/toolkit, B200 capability, and exact pins.
2. SFT canary: five optimizer updates, checkpoint save, finite loss, W&B finish.
3. SimCT canary: ten optimizer updates from the SFT checkpoint.
4. Numerical qualification: at least twenty SimCT updates, with the full-run LR
   scheduler horizon retained so updates after the 5% warmup are observed.

Tiers 1-3 establish portability and execution correctness. They do not reproduce
the paper's two-epoch training or five-seed evaluation results.
